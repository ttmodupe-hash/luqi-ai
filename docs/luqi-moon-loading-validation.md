# Moon homepage loading correction and acceptance

The original Moon PR added the complete lunar model to the static homepage import graph. The existing Startup Payload job rejected that candidate (512,867 raw / 153,466 gzip startup JS bytes against its historical 529,636 / 155,514 baseline; the unchanged guard requires at least 5% reduction in both).

MoonNowPanel is now a small lazy-loading/error boundary. The original calculation, location controls and styling move byte-for-byte to MoonNowContent, downloaded automatically when the homepage renders. The first corrected build passed 37 numerical/input/privacy tests and 13 interface/loading tests, strict types and production build. Its initial gzip graph still exceeded the existing threshold; the same-run browser install failed because Playwright 1.58.2 does not support the ubuntu-latest image's Ubuntu 26.04. No browser success was claimed for that run.

The follow-up pins the browser job to Ubuntu 24.04 and defers the existing DiscoveryDeck and CreatorPackPreview into one automatic below-hero chunk. Both components remain unchanged, at the same homepage position, with an independent loading/recovery boundary. The core shell, tool search, accounts and Moon wrapper remain available independently. New tests exercise automatic discovery loading, interest selection, Mix it up and the actual creator link. No page is replaced with a placeholder and no click is required to activate the Moon.

This reduces the static startup graph, not necessarily total data transferred after all homepage panels load. No claim of measured network latency improvement is made. The old performance thresholds and baseline are unchanged. Home.tsx changes must be reconciled with current-main copy improvements by the PR merge, not an overwrite of main.

A delayed or failed Moon download affects only that panel. No fictional phase is substituted, no automatic page reload is performed and no account/provider request is introduced. Manual reload explicitly warns about unsaved work and in-memory sign-in. Existing calculation and location tests import the unchanged content; additional tests cover the entry boundary, preserved surrounding draft, rejection privacy and explicit-only reload.

The dedicated workflow builds the real frontend and exercises Chromium/WebKit at 1366px, 390px and 320px. It also deliberately fails the actual emitted Moon chunk, checks homepage tool search still works, removes the synthetic failure, and tests user-requested full reload. Every API write/external request is blocked before transport; this is non-production browser acceptance, not physical-device or live-PWA certification. Screenshots and a revision-labelled report are retained. Numerical accuracy expansion remains separate; no original tolerance or test is weakened.

Actual revised checks must be inspected before asserting success. This is on the existing PR branch only. No production deployment, service flag, secret, database, budget, DNS or payment change is made.
