# Dependency repair — 24 October 2026

Issue #205 records the failed baseline audits. The repair pins Zod 4.6.7 and
OpenAI SDK 7.43.0 in the root and standalone app. The separately metered AI
gateway retains its existing transport, activation and spending controls.

The first candidate SDK 6.0.0 declared a Zod 4 peer range, but the new regression
found its helper converted a real v4 schema into an empty JSON schema. Its
source imported v3 types/conversion. That candidate was rejected, not deployed,
and the test was preserved. SDK 7.43.0 explicitly handles v4 schemas and passed
the same schema/transport tests plus the scoped compiler. Peer metadata alone
is not compatibility proof.

All resolved root/app Zod copies are checked; there is no first-party switch
to `zod/v3` to conceal the old implementation. Existing record schemas already
supply both key and value arguments. Authentication, notes, tRPC and Omega
contracts must pass against v4 before merge. Bounded collections need explicit
limits even with the upstream patch. Unreviewed legacy provider routes stay closed.

The isolated edge package keeps Wrangler 4.152.0. Its package-local Undici
override pins 7.30.1. An initial Miniflare-scoped override passed a lock audit
but failed a subsequent `npm ci` consistency check; that candidate was rejected.
The corrected package-local override passed a fresh clean install and installed
package audit. This override is confined to the edge tooling package, not the
root application. Worker dry-run validation is required before release; no
Cloudflare deployment or DNS change is part of the repair.

Root/app npm and Bun locks were regenerated by their package managers without
dependency lifecycle scripts. Root changes remove obsolete SDK transport
packages and deduplicate Zod; npm also records previously absent optional
Tailwind WASI subdependencies. Review the committed diff. No integrity hashes
were invented, no audit exclusions added, and no `audit fix --force` was used.

The temporary fixed-branch resolution workflow was removed from the release
tree. It checked its expected remote head and could commit only the reviewed
manifests/locks and two SDK-version assertions to the named repair branch. Its
commands never merged or wrote main. Permanent validation is contents-read only.

- Installed-tree root production/full, standalone app, desktop, Bun, edge and
  resolved Python audits at the final PR revision; prior clean reports expire.
- Eighteen new collection short-circuit, version and SDK synthetic-transport
  regressions, existing web/browser contracts, scoped types, actual production
  container startup and disposable MySQL/auth/restore fixtures.
- Exact-revision Railway SUCCESS and public release checks after an approved
  merge. A passing audit does not establish incident clearance, a production
  restore, a paid AI reply, merchant readiness or full product completion.
